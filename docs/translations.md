# Writer interface translations

Writer uses Lingui 6.9 macros, generated English/context IDs, PO source catalogues and compiled ICU JSON. Interface language is independent of a manuscript's `lang`: citation terms, hyphenation, manuscript text, exported prose, source metadata, record paths and user-created labels are not translated.

## Runtime

`apps/writer/src/i18n/app.ts` injects the single Lingui instance exported by the shared UI package. English JSON is synchronous. French, German, Spanish, Japanese, Korean, Brazilian Portuguese (`pt`), Russian and Simplified Chinese (`zh`) are lazy JSON chunks served by the same deployment. Browser language negotiation is used until an explicit choice is saved in `mdbase-writer:interface-locale`. Unavailable browser storage does not block selection. A failed chunk request keeps the current language and saved choice.

The language picker is available on the home/sign-in chrome and in workspace settings, so it does not compete with the manuscript toolbar on narrow screens. The root provider covers dialogs and portals. The editor's separately mounted selection toolbar uses the same instance. Language changes reconfigure CodeMirror's phrases and editor chrome in place rather than recreating the editor or changing its text/history. Chapter switches reuse already-loaded phrases: a redundant asynchronous decoration refresh before the new view's first measurement discarded its retained scroll anchor. The unchanged browser reliability scenario exposed this regression; a real-runtime unit regression also checks that an already-localized chapter receives no deferred refresh. The runtime updates `<html lang>`; display-only dates, numbers and relative times use the interface locale.

The shared runtime is given `i18n` from `@mdbase-dev/ui/i18n` (the same core singleton), so core macros, React context and presentation helpers share one translator without custom module aliases. English is initialized before non-React helpers run; tests load that same real runtime.

## Authoring

From `apps/writer`:

```sh
pnpm i18n:extract
# Author/review src/i18n/locales/<locale>/messages.po locally.
pnpm i18n:compile
pnpm i18n:check
```

`i18n-policy.json` explicitly allowlists reviewed unchanged keyboard key legends (including Japanese), `ID`, Word/DOCX, German cognates (including “Problem”), Spanish/Portuguese Editor/Zoom, Portuguese Layout / “via mdbase Connect”, and reviewed French cognates (e.g. Collection, Source, Citation, Note, Page, Article) / “via mdbase Connect”. It does not exempt whole catalogues or English prose. New identical terms need review; for example, English “click” in a Chinese shortcut hint is not accepted as a keyboard key name.

Use `Trans` for complete sentences with rich markup and ICU plurals for counts. Use `t` in presentation helpers and accessible labels. Add semantic context to ambiguous short messages. Module-level option labels must be lazy getters or rendered on demand, never translations captured before locale selection. Stable command IDs, keyboard bindings, format keys and record values remain untranslated.

Shared UI owns its catalogues. The runtime composes `uiCatalogues` from `@mdbase-dev/ui/i18n` via `libraries`; no library source or provisional collection-copy dictionary is extracted into Writer. App and library target chunks load together before activation. Collection names remain user data, as does the protected `{#fig-plan}` Markdown example. The final vendored UI integration snapshot is `vendor/mdbase-dev-ui-0.1.0-beta.141-a36fa009.tgz` (SHA-256 `e7199463d7f4d282cfd6f5f16e71dc1aa1029330a634f43112ae5b2f63dea7a0`). This replaces `852df21f`: all nine installed compiled UI catalogues have exactly 197 active IDs and no obsolete `nzHlj8` (`Close {0}`) entry. The shared CommandPalette also exposes the new presentation-only `groupLabel` callback; Writer needs no app-local adaptation. Strict runtime composition correctly rejects mismatched compiled entries: an untranslated app/shared catalogue must not silently override an authored one. Source comparison against portal's current shared catalogues found one real discrepancy: Russian `Remove` (`t_YqKh`) was `Убрать` in Writer vs `Удалить` in shared UI; Writer was explicitly aligned to `Удалить`. The other seven locales agreed on all overlapping IDs. The shared CLI's `check --compose 'node_modules/@mdbase-dev/ui/dist/locales/{locale}/messages.json'` checks every app/library overlap in all nine locales as part of normal check/build; runtime tests also activate all eight target languages without mocking or bypassing collision checks. The temporary app-local overlap script was replaced by this shared gate. Never bypass the collision guard to make an integration test pass.
