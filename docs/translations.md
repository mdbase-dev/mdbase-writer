# Writer interface translations

Writer uses Lingui 6.9 macros, generated English/context IDs, PO source catalogues and compiled ICU JSON. Interface language is independent of a manuscript's `lang`: citation terms, hyphenation, manuscript text, exported prose, source metadata, record paths and user-created labels are not translated.

## Runtime

`apps/writer/src/i18n/app.ts` injects the single Lingui instance exported by the shared UI package. English JSON is synchronous. French, German, Spanish, Italian (`it`, picker endonym “Italiano”), Japanese, Korean, Brazilian Portuguese (`pt`), Russian and Simplified Chinese (`zh`) are lazy JSON chunks served by the same deployment. Browser language negotiation is used until an explicit choice is saved in `mdbase-writer:interface-locale`. Unavailable browser storage does not block selection. A failed chunk request keeps the current language and saved choice.

The language picker is available on the home/sign-in chrome and in workspace settings, so it does not compete with the manuscript toolbar on narrow screens. The root provider covers dialogs and portals. The editor's separately mounted selection toolbar uses the same instance. Language changes reconfigure CodeMirror's phrases and editor chrome in place rather than recreating the editor or changing its text/history. Resolved phrase dictionaries are cached outside the keyed editor's lifetime, so chapter remounts install the active phrases synchronously without a deferred decoration refresh racing retained-scroll measurement. First use of a target language remains lazy; English remains synchronous. See the investigation below and the keyed, real-runtime en/ja/de/it regression in `Editor.recovery.test.tsx`. The runtime updates `<html lang>`; display-only dates, numbers and relative times use the interface locale.

The shared runtime is given `i18n` from `@mdbase-dev/ui/i18n` (the same core singleton), so core macros, React context and presentation helpers share one translator without custom module aliases. English is initialized before non-React helpers run; tests load that same real runtime.

## Authoring

From `apps/writer`:

```sh
pnpm i18n:extract
# Author/review src/i18n/locales/<locale>/messages.po locally.
pnpm i18n:compile
pnpm i18n:check
```

`i18n-policy.json` explicitly allowlists reviewed unchanged keyboard key legends (including Japanese), `ID`, Word/DOCX, German cognates (including “Problem”), Spanish/Portuguese Editor/Zoom, Portuguese Layout / “via mdbase Connect”, and reviewed French cognates (e.g. Collection, Source, Citation, Note, Page, Article) / “via mdbase Connect”. Italian adds 21 reviewed identical entries: 17 keyboard/shortcut legends, the standard software term “Editor”, the product/format “Word (DOCX)”, and two interpolated location fragments using the Italian preposition “in”. It does not exempt whole catalogues or English prose. New identical terms need review; for example, English “click” in a Chinese shortcut hint is not accepted as a keyboard key name.

Use `Trans` for complete sentences with rich markup and ICU plurals for counts. Use `t` in presentation helpers and accessible labels. Add semantic context to ambiguous short messages. Module-level option labels must be lazy getters or rendered on demand, never translations captured before locale selection. Stable command IDs, keyboard bindings, format keys and record values remain untranslated.

Shared UI owns its catalogues. The runtime composes `uiCatalogues` from `@mdbase-dev/ui/i18n` via `libraries`; no library source or provisional collection-copy dictionary is extracted into Writer. App and library target chunks load together before activation. Collection names remain user data, as does the protected `{#fig-plan}` Markdown example. Shared UI is pinned to the published npm version `0.1.0-beta.148`. All ten installed compiled UI catalogues have exactly 197 active IDs and no obsolete `nzHlj8` (`Close {0}`) entry. The shared CommandPalette also exposes the new presentation-only `groupLabel` callback; Writer needs no app-local adaptation. Strict runtime composition correctly rejects mismatched compiled entries: an untranslated app/shared catalogue must not silently override an authored one. Source comparison against portal's current shared catalogues found one real discrepancy: Russian `Remove` (`t_YqKh`) was `Убрать` in Writer vs `Удалить` in shared UI; Writer was explicitly aligned to `Удалить`. The other seven locales agreed on all overlapping IDs. The shared CLI's `check --compose 'node_modules/@mdbase-dev/ui/dist/locales/{locale}/messages.json'` checks every app/library overlap in all ten locales as part of normal check/build; runtime tests also activate all nine target languages without mocking or bypassing collision checks. The temporary app-local overlap script was replaced by this shared gate. Never bypass the collision guard to make an integration test pass.

### Scroll-retention investigation

The residual paragraph-83→91 shift was **introduced by i18n**, not reproduced on main. `WorkspaceView` renders `<Editor key={active}>`: each chapter switch destroys and remounts the component. The previous fix cached phrases only in component refs, which survive an ordinary rerender but **not a keyed remount**. Thus Japanese/German chapters started with English phrase refs again, and even an already-imported target dictionary delivered a promise callback that reconfigured the language compartment and refreshed chapter/live-preview decorations while CodeMirror was restoring its virtualised viewport. The previous unit test changed props on the same component and missed that lifetime.

The fix retains resolved dictionaries in a bounded-by-supported-locales module cache. A remount installs its cached active phrases in the initial editor extensions and issues no deferred language/decorations dispatch. Actual locale changes still reconfigure the existing view, with cancellation guarding stale callbacks. There are no restore retries, artificial delays, relaxed anchor thresholds or skipped assertions.

Controlled comparison used the **same original chapter/history/selection/scroll scenario**, unchanged assertions and 1500×950 fresh contexts, ten iterations per browser locale en/ja/de:
- Separate detached worktree `../writer-scroll-main`, fetched `origin/main` **4c853dca6fafb52c6ca7d4bccf046b3272a52640**: **30/30 passed**. Main has English UI; browser locales were varied identically.
- Previous i18n head **b9b79e373837390a87bbe1e5a5df363bcd5a62fe**: English **10/10 passed**; Japanese/German **20/20 failed**, restoring paragraph91 instead of83.
- Corrected source: **30/30 passed** with geometry observations. Scroller width611px, content width574px and height864px stayed constant before/after restore in all three locales. This was not translated chrome changing the available width or a user-triggered locale switch.
- The real-runtime keyed-remount unit test fails deterministically for ja/de before the source fix and passes for en/ja/de after it. It verifies both synchronous target phrases and the absence of deferred dispatch before any animation-frame measurement; no translator mock is used.
